# 관리자 가이드 — 배포 · 업데이트 · 롤아웃

## 최초 구축 (관리자 1명, 한 번)

1. 이 템플릿을 회사 **private 레포**로 만듭니다.
2. 클론 → `bash tools/bootstrap.sh` → 클로드 코드에서 "세팅해줘"
3. 온보딩 Step 1~2 진행: 회사 인터뷰 → **자료 흡수(INGEST)**
4. 결과를 커밋합니다. **커밋 전 반드시 확인**:
   ```bash
   git status
   git check-ignore -v 90_ME/profile.md   # 개인 파일이 제외되는지
   ```
   `00_COMPANY/*.md` 실파일은 기본적으로 `.gitignore` 대상입니다.
   회사 정본을 **전 직원과 공유하려면** 이 항목들을 `.gitignore`에서 빼고
   커밋하세요. 그때 개인정보가 안 섞였는지 한 번 더 봅니다.

## 직원 배포

직원에게 주는 것은 이 세 줄이면 충분합니다.

```bash
git clone <레포> ~/AI/company && cd ~/AI/company
bash tools/bootstrap.sh
claude
```
그리고 "세팅해줘".

온보딩이 회사 레이어가 이미 채워진 걸 감지하고 **본인 직무 + 개인 설정만**
5분짜리로 진행합니다.

## 롤아웃 순서 (세 단계로 나눠 배포합니다)

| 단계 | 대상 | 목표 |
|---|---|---|
| 1 | 1~2명 파일럿 | 실제로 쓰이는지 확인. `00_COMPANY` + **본인 직무 폴더 하나**만 |
| 2 | 파일럿 + 2주 | 실사용된 절차만 `20_PLAYBOOKS/`로 승격 |
| 3 | 전사 | ONBOARDING을 신입 시점으로 검증한 뒤 |

**2단계를 건너뛰지 마세요.** 미리 쓴 SOP는 거의 다 안 맞습니다.
써보고 나서 승격하는 게 이 폴더를 살립니다.

## 업데이트 배포

회사 정본이나 플레이북을 고쳤으면 커밋 → 푸시. 직원은:
```bash
git pull && bash tools/bootstrap.sh
```

개인 파일과 로컬 실데이터는 추적 대상이 아니라 덮어써지지 않습니다.

## 직원이 개선한 것을 회수하기

직원이 좋은 플레이북을 만들면 브랜치·PR로 받습니다. 이게 이 구조의 복리 지점입니다.
단 PR 리뷰에서 **개인정보·개인 레이어 유출**을 반드시 확인하세요.

## 자주 나오는 질문

**Q. 직원 개인 폴더를 회사가 볼 수 있나요?**
없습니다. `90_ME/`는 로컬에만 있고 git에 안 올라갑니다. 다만 이건 신뢰의 문제이기도
하니, 도입할 때 **명시적으로 말해주세요.** 안 그러면 개인 레이어가 안 쓰입니다.

**Q. 계약서·정산서를 넣어도 되나요?**
기준은 하나입니다 — **"이 레포를 받는 직원 전원이 봐도 되는가?"** 그렇다면 넣고,
아니면 별도 레포로 분리하거나 원본 시스템에 둡니다. 폴더를 나누는 것으로는
통제되지 않습니다. 자격증명·주민번호는 무조건 제외입니다.

**Q. 인사·급여 자료는요?**
**넣지 않습니다.** 워크스페이스 범위 밖이고(`policy/scope.md`), 스캐너가 적재를
차단합니다. 직원이 관련 질문을 하면 에이전트가 담당 팀으로 안내합니다.

**Q. 이미 사내 위키·노션이 있는데요?**
대체가 아니라 색인으로 씁니다. INGEST로 export를 흡수해 카드만 만들고, 원본은
기존 시스템에 두고 카드에 링크를 겁니다.
