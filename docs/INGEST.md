# INGEST — 정리 안 된 회사 자료 흡수 절차

> **에이전트가 따라가는 절차입니다.** 사용자가 자료 뭉치·폴더·드라이브 경로를 주면
> 이 문서대로 진행합니다.

## 전제

- 회사 지식은 원래 정리돼 있지 않습니다. 정리를 요구하지 않습니다. **그대로 받습니다.**
- 확장자 제약 없습니다. 모르는 포맷도 목록에는 남깁니다. **버리지 않습니다.**
- 원본은 수정도 이동도 하지 않습니다. 복사만 합니다.
- 분류는 **기계가 하지 않습니다.** 기계는 사실만 모으고, 의미 분류는 에이전트가
  하되 사람이 승인합니다.

---

## 1단계 — 기계 스캔

```bash
python3 tools/ingest_scan.py "/경로/회사자료" "/다른/경로"
```

경로가 없으면 `ingest/_INBOX/`에 그냥 복사해 넣으라고 안내하고
`python3 tools/ingest_scan.py ingest/_INBOX` 로 돌립니다.

산출물:
- `ingest/_scan/manifest.jsonl` — 파일당 JSON 1줄 (경로·크기·날짜·해시·본문 미리보기·플래그)
- `ingest/_scan/REPORT.md` — 전체 그림

---

## 2단계 — 먼저 보고, 그다음 질문

`REPORT.md`를 읽고 사용자에게 **분류하기 전에** 보고합니다:

- 몇 개 / 총 용량 / 어떤 종류 / 어느 시기
- 🔴 적재 차단 건수 (자격증명·주민번호·인사/급여) ← **먼저 말합니다**
- 최상위 폴더 분포 ← **원본 폴더 구조가 이 회사의 실제 분류입니다.**
  여기서 발견한 구조를 존중하세요. 내 마음대로 새 체계를 강요하지 않습니다.
- 시크릿 🔴 / 민감 🟡 / 중복 / 추출 불가 건수

그리고 **물어봅니다**:
- "이 폴더명 `{모르는 이름}`은 뭔가요?"
- "이 중 지금도 유효한 건 어디까지인가요? 옛날 것은 아카이브로 보낼까요?"
- "지금 당장 자주 찾게 될 자료는 뭔가요?" ← 여기부터 카드를 씁니다

**분류안을 내기 전에 최소 한 번은 질문합니다.** 회사 폴더 이름의 뜻은 밖에서
추측할 수 없습니다. 질문 없이 만든 분류안은 거의 다시 뒤집힙니다.

---

## 3단계 — 분류안 작성

`manifest.jsonl`을 **200개씩 배치로** 읽습니다. 한 번에 다 읽지 마세요.

각 항목에 대해 `ingest/plan.jsonl` 한 줄을 씁니다:

```json
{"path":"/원본/절대경로","action":"copy","dest":"30_KNOWLEDGE/2024/계약/OO계약서.pdf","reason":"2024 거래처 계약 원본"}
```

### 분류 기준

| 자료 성격 | 목적지 |
|---|---|
| 회사 소개·미션·정책 원문 | `00_COMPANY/` (내용은 정본 파일에 반영, 원본은 30_KNOWLEDGE) |
| 계약·정산·리서치·회의록·기획서 | `30_KNOWLEDGE/{연도}/{분류}/` |
| 반복 절차·매뉴얼·체크리스트 | `20_PLAYBOOKS/` (요약해서 재작성, 원본도 보관) |
| 로고·서식·템플릿 | `40_ASSETS/` |
| 진행 중 프로젝트 자료 | `50_PROJECTS/{프로젝트}/` |
| 끝난 프로젝트 | `80_ARCHIVE/` |
| 판단 안 되는 것 | `ingest/_UNSORTED/` ← **버리지 말고 여기로** |
| 🔴 자격증명·주민번호 | `"action":"skip"` — 원본 위치만 보고 |
| 🔴 인사·급여·근로계약·이력서 | `"action":"skip"` — **범위 밖**(`policy/scope.md`). 요약도 만들지 않음 |

### 규칙

- **중복(`duplicate_of`)은 한 번만** 적재합니다. 나머지는 skip + reason에 원본 명시.
- 개인 파일(누군가의 사적 문서)이 섞여 있으면 skip하고 보고합니다.
- **직원 개인 정보가 든 파일**(명단·급여·평가·근로계약)은 skip합니다. 스캐너가
  놓쳐도 에이전트가 잡습니다. 이 레포는 전 직원이 공유하기 때문입니다.
- 적재 판단의 기준선: **"이 레포를 가진 사람 전원이 봐도 되는가?"**
  아니면 넣지 않고, 별도 레포 분리를 제안합니다.
- 판단이 안 서면 `_UNSORTED`로. 억지로 분류하는 것보다 낫습니다.

## 4단계 — 승인 → 적용

먼저 시뮬레이션:
```bash
python3 tools/ingest_apply.py --plan ingest/plan.jsonl --dry-run
```

건수와 대표 예시를 사용자에게 보여주고 승인받은 뒤:
```bash
python3 tools/ingest_apply.py --plan ingest/plan.jsonl
```

`ingest/applied.jsonl`에 전부 기록됩니다. 되돌릴 근거입니다.

---

## 5단계 — 색인 카드 (생략 금지)

적재한 문서마다 `30_KNOWLEDGE/cards/{YYMMDD}_{분류}_{제목}.md`를 씁니다.
형식은 `30_KNOWLEDGE/CLAUDE.md` 참조.

**카드 없는 원본은 없는 것과 같습니다.** PDF·xlsx는 의미 검색이 안 되기 때문입니다.

### 우선순위

전부 한 번에 쓰지 마세요. 순서:
1. 2단계에서 사용자가 "자주 찾는다"고 한 것
2. 최근 1년치
3. 계약·정산처럼 정확도가 중요한 것
4. 나머지는 필요할 때 (`INDEX.md`에 "카드 미작성" 표시해 두고)

카드를 쓸 때마다 `30_KNOWLEDGE/INDEX.md`에 한 줄 추가합니다.

### 본문 추출이 안 된 파일 (`.hwp`, 스캔 PDF 등)

파일은 이미 보관돼 있습니다. 카드는 파일명·경로·사용자 설명으로 씁니다.
**내용을 추측해서 쓰지 마세요.** 모르는 부분은 `내용 미확인`이라고 적습니다.

## 6단계 — 마무리 보고

- 적재 N건 / 카드 M장 / `_UNSORTED` K건 / skip S건(사유별)
- 🔴 시크릿 파일 목록과 원본 위치 → 사용자가 직접 처리
- `_UNSORTED`를 어떻게 할지 물어봅니다 (나중에 다시, 아니면 지금 같이)
- 지금 바로 시험해볼 질문 3개를 제시 (예: "작년 OO 계약 조건이 뭐였지?")

이미 넣은 파일은 자동으로 걸러집니다.
