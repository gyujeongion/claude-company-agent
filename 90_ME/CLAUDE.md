# 90_ME — 개인 레이어

> **이 폴더는 회사 레포에 올라가지 않습니다.** `.gitignore`가 `90_ME/*` 전체를
> 제외합니다 (이 안내 파일과 `*.example` 시드만 추적됨). 직접 확인:
> ```bash
> git check-ignore -v 90_ME/profile.md
> ```

## 이 보장의 정확한 범위 (읽고 판단하세요)

애매하게 "회사가 안 본다"고 하면 결국 아무도 안 믿고 이 레이어는 죽습니다.
그래서 정확히 적습니다.

**보장되는 것**
- 이 폴더의 내용은 커밋·푸시되지 않습니다. 동료도, 관리자도 **레포를 통해서는**
  볼 수 없습니다. 실수로 `git add .`를 해도 들어가지 않습니다.
- 회사 레이어를 업데이트(`git pull`)해도 이 폴더는 덮어써지지 않습니다.

**보장되지 않는 것**
- 파일은 **이 컴퓨터에 그대로 있습니다.** 회사 지급 장비이고 관리 정책(원격 관리·
  백업·모니터링)이 걸려 있다면, 이론적으로 관리자가 로컬 파일에 접근할 수 있습니다.
  이건 이 워크스페이스가 아니라 **장비 정책의 문제**이고, 여기서 해결할 수 없습니다.
- 회사 장비 정책이 어떤지 모르겠으면 담당자에게 물어보세요. 그게 정확한 답을 얻는
  유일한 방법입니다.

**결론**: 회사 눈에 절대 띄면 안 되는 내용이라면, 회사 장비 밖에서 다루세요.
그 정도가 아닌 일반적인 개인 업무·커리어 정리라면 여기가 맞는 자리입니다.

## 뭘 넣나

| 파일 | 내용 |
|---|---|
| `profile.md` | 내가 누구인지 — 직무·강점·지금 신경 쓰는 것 |
| `how_to_work_with_me.md` | 에이전트가 나를 어떻게 대해야 하는지 |
| `personal/` | 회사와 무관한 개인 용도 (일정·공부·글쓰기·리서치·취미 등) |

`personal/` 아래는 자유롭게 만드세요. 개인 프로젝트별 파일을 두는 게 편합니다.

## 에이전트 규칙 (중요)

1. **회사 데이터를 개인 판단 근거로 인용하지 않습니다.**
   회사 문서에서 본 수치·내부 사정을 개인 상담에 끌어오지 마세요.
2. **개인 레이어 내용을 회사 산출물에 넣지 않습니다.**
   여기서 알게 된 사정은 회사 문서·메일·보고에 절대 등장하지 않습니다.
3. **회사 정책·대외 톤은 여기서 OFF**입니다. 개인 커리어 고민에 브랜드 가이드를
   적용하는 건 틀린 답입니다.
4. 개인 맥락 작업의 산출물은 **`90_ME/` 안에만** 씁니다.

`boundary_gate.py` 훅이 개인 키워드에서 이 규칙을 상기시킵니다.

## 회사 계정으로 개인 일을 해도 되나

이 워크스페이스는 그러라고 만든 것입니다. `00_COMPANY/policy/ai_usage.md`의
분류 D(개인)가 이 용도를 명시합니다.

> 위의 "보장 범위"와 헷갈리지 마세요. **써도 되는가**(= 된다)와
> **누가 볼 수 있는가**(= 레포로는 못 본다, 로컬은 장비 정책 문제)는 다른 질문입니다.
