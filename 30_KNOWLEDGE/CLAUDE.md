# 30_KNOWLEDGE — 회사 자료 창고

INGEST로 흡수한 문서와 그 **색인 카드**가 사는 곳.

## 구조

```
30_KNOWLEDGE/
├── INDEX.md      전체 카드 한 줄 목록 (최신이 위)
├── cards/        문서 1개 = 카드 1장 (.md). 검색은 여기서 일어난다
└── {연도}/{분류}/ 원본 파일 (PDF·docx·xlsx 등)
```

## 왜 카드인가

PDF·xlsx는 의미 검색이 안 됩니다. 원본만 쌓으면 6개월 뒤 아무것도 못 찾습니다.
카드는 **원본을 대신 찾아주는 색인**입니다. 원본 1개당 카드 1장이 원칙입니다.

## 조회 순서 (반드시 이 순서)

```
1. INDEX.md 훑기        ← 뭐가 있는지
2. 해당 cards/*.md 읽기  ← 요약·핵심 수치·출처
3. 원본은 정말 필요할 때만 열기
```
원본부터 열지 마세요. 컨텍스트가 순식간에 찹니다.

## 카드 형식

```markdown
# {문서 제목}

- 종류: 계약 / 정산 / 기획 / 리서치 / 회의록 / 기타
- 날짜: YYYY-MM-DD (문서 기준일. 모르면 파일 수정일 + "(추정)")
- 원본: `30_KNOWLEDGE/2024/계약/파일명.pdf`
- 관련: [[다른-카드-이름]]
- 취급: 사내한정 / 대외가능 / 인용주의   ← 접근 제어가 아니라 **주의 라벨**

## 한 줄

{이 문서가 뭔지 한 문장}

## 핵심

- {판단에 필요한 사실·수치. 전문 복사 금지}

## 주의

{이 문서를 인용할 때 조심할 것. 만료됐다든가, 개정본이 있다든가}
```

## 규칙

- **문서에 없는 내용을 카드에 쓰지 않습니다.** 카드가 원본과 어긋나면 창고 전체가
  못 믿을 것이 됩니다. 추론을 넣으려면 `[AI]`를 붙이세요.
- 날짜가 불확실하면 `(추정)`을 답니다.
- **여기 있는 것은 레포를 가진 전원이 봅니다.** 그래도 되는 자료만 넣습니다.
  `취급:` 라벨은 주의 표시일 뿐 접근 제어가 아닙니다 (`policy/security.md`).
- **인사·급여·근로계약·직원 개인 정보는 카드로도 만들지 않습니다** (`policy/scope.md`).
- 사람 이름은 업무상 꼭 필요한 경우(거래처·아티스트 등)만. 내부 직원은 팀·역할로.
- 개정본이 들어오면 옛 카드를 지우지 말고 `status: superseded` + 새 카드 링크.
