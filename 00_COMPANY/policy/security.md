# 보안 · 민감정보 취급

## 절대 워크스페이스에 넣지 않는 것

- API 키·토큰·비밀번호·`.env`·인증서·개인키
- 주민등록번호·여권번호·계좌번호·카드번호
- 인사·급여·근로계약 관련 일체 → `policy/scope.md` (범위 밖)
- 직원 개인을 식별하는 정보 (실명 명단·직급·연락처·평가)

`tools/hooks/secret_guard.py`가 이 파일들의 읽기를 도구 단계에서 차단합니다.
차단이 뜨면 우회하지 말고, 값이 정말 필요한지부터 되물으세요.

## 등급 — 가장 자주 오해되는 부분

**이 레포에 들어간 것은 레포를 가진 전원이 봅니다.** 폴더를 나누든, 카드에
`취급: 사내한정`이라고 적든 마찬가지입니다. 파일 권한이 아니라 **글자**일 뿐입니다.
경로 하나 잘못 공유되면 그대로 열립니다.

판단 기준은 하나입니다.

> **"이 레포를 가진 사람 전원이 봐도 되는가?"**
> 아니라면 → 넣지 않습니다. 별도 레포로 분리하거나, 원본 시스템(회계·인사
> 프로그램)에 그대로 둡니다.

카드의 `취급:` 표기는 **사람에게 주는 주의 라벨**이지 접근 제어가 아닙니다.

## 민감하지만 넣어도 되는 것

계약서·정산서·기획 문서 등은, 위 기준을 통과한다면 워크스페이스에 둘 수 있습니다. 단:

1. **원본은 `30_KNOWLEDGE/`에**, 요약·수치는 색인 카드에.
2. 카드에는 **판단에 필요한 최소 정보만** 적습니다. 전문이 필요하면 원본을 엽니다.
3. 외부로 나가는 산출물에는 원본 수치를 그대로 옮기지 않습니다 —
   무엇을 공개해도 되는지 매번 확인합니다.
4. **내부 직원 이름은 쓰지 않습니다.** 팀·역할로 씁니다. 거래처·아티스트처럼
   업무상 반드시 필요한 이름만 예외입니다.

## INGEST 시

> 탐지는 **최선형**입니다. 파일명과 본문 앞부분만 봅니다. 스캔 이미지 PDF나
> 미지원 포맷에 숨은 민감정보는 놓칩니다. 도구를 믿고 넣지 말고, **넣어도 되는 것만**
> 넣으세요 (위 '등급' 항목).

- 스캐너가 시크릿·주민번호 패턴을 잡으면 그 파일은 **적재하지 않습니다.**
  원본 위치만 사용자에게 알리고, 사용자가 직접 처리합니다.
- 파일명·내용에 `급여/연봉/인사/근로계약/이력서/평가` 등이 있으면 **빨간 플래그**가
  붙고 적재가 차단됩니다. 위치만 보고하고 손대지 않습니다.
- 파일명에 `계약/정산/대외비` 등이 있으면 노란 플래그가 붙습니다.
  적재는 되지만, 아래 '등급' 항목을 먼저 읽으세요.

## 유출 경로 네 가지 (실제로 여기서 납니다)

1. **대외 문서에 내부 수치.** → 발송 체크리스트 통과.
2. **개인 레이어 내용이 회사 산출물로.** → 회사 산출물의 근거는 `00`~`80`에서만 가져옵니다.
3. **git 커밋.** → 실데이터 파일은 전부 `.gitignore`. 커밋 전
   `git status`로 확인하고, 개인 파일이 보이면 멈추고 보고.
4. **직원 간 경로 오공유.** → 동료에게 폴더·경로를 넘길 때 그 안에 그 사람이
   몰라야 할 것이 없는지 봅니다. 애초에 그런 걸 안 넣는 게 위 '등급' 원칙입니다.

## 사고가 났으면

숨기지 말고 즉시 보고합니다. 보고 대상은 본인이 압니다 — 에이전트는 조직 정보를
갖고 있지 않으므로 대신 정해주지 않습니다.
에이전트는 사용자가 실수를 발견하면 **되돌리는 절차를 먼저** 안내합니다.
